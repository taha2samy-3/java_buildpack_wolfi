# Security policy

## Supported versions

Only the latest minor release receives security fixes. Runtime dependencies (Temurin, Wolfi packages, Paketo buildpacks) are refreshed weekly, so rebuilding on the latest release picks up upstream fixes.

## Reporting a vulnerability

Report vulnerabilities privately through [GitHub private vulnerability reporting](https://github.com/taha2samy-3/java_buildpack_wolfi/security/advisories/new). Do not open public issues for security problems.

Include the affected version or image digest, the configuration used (for example `BP_JVM_FIPS_ENABLED`), reproduction steps and the impact you observed. You will receive an acknowledgement within 5 working days and a status update at least every 14 days until the report is resolved.

## Scope

In scope: the buildpack code, launch helpers, stack images, release workflows and the FIPS configuration generated by the buildpack.

Out of scope: vulnerabilities in Eclipse Temurin, Bouncy Castle, Wolfi packages or Paketo buildpacks themselves. Report those upstream; we will update the pinned versions once a fix is available.

## Verifying artifacts

Every release image is signed with Sigstore keyless signing and carries SLSA Build Level 3 provenance and a CycloneDX SBOM attestation. See the [supply chain documentation](https://taha2samy-3.github.io/java_buildpack_wolfi/security).
