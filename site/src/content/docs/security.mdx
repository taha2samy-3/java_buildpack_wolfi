## SLSA Build Level 3

Releases are built only by the `release.yml` workflow on GitHub-hosted, ephemeral runners when a `vX.Y.Z` tag is pushed. Provenance is generated by the [SLSA GitHub generator](https://github.com/slsa-framework/slsa-github-generator) in an isolated reusable workflow, so the build steps cannot forge it. It is signed with Sigstore and pushed next to each image.

<Figure src="release-pipeline.svg" alt="Release pipeline: tag, CI, stacks and buildpacks, builder, SLSA provenance, signing and SBOM, GitHub release, docs" width="860" />

Every release publishes five images, and each one gets:

- SLSA v1 provenance (`slsa-verifier`),
- a keyless Sigstore signature (`cosign verify`),
- a CycloneDX SBOM attestation (`cosign verify-attestation --type cyclonedx`),
- a Grype vulnerability report in the workflow summary.

## Verify a release

```sh
IMAGE=[[registry]]/wolfi-java-builder@sha256:<digest from the release notes>

slsa-verifier verify-image "$IMAGE" \
  --source-uri github.com/taha2samy-3/java_buildpack_wolfi \
  --source-tag v[[latest]]

cosign verify "$IMAGE" \
  --certificate-identity https://github.com/taha2samy-3/java_buildpack_wolfi/.github/workflows/release.yml@refs/tags/v[[latest]] \
  --certificate-oidc-issuer https://token.actions.githubusercontent.com
```

The release notes on the [Releases](releases.html) page list the digest of every image and contain these commands with the values filled in.

## Inputs are pinned

- Wolfi base images and the CNB lifecycle by digest.
- Paketo buildpacks by version and digest.
- Temurin JDK and JRE archives by SHA-256, cross-checked between the Adoptium API and the GitHub release before they enter `buildpack.toml`.
- Bouncy Castle jars by SHA-256, with `bc-fips` held at the CMVP validated version.
- GitHub Actions by commit SHA.

Dependabot and a weekly workflow open pull requests for updates, so every change to an input is reviewed.

## Hardening in the repository

- `permissions: {}` at workflow level, with the minimum per job.
- `persist-credentials: false` on every checkout.
- CodeQL for Go and GitHub Actions, OpenSSF Scorecard, dependency review on pull requests, `govulncheck` and `golangci-lint` with `gosec`.
- Reproducible Go builds (`-trimpath`, empty build ID, fixed file timestamps).

## Reporting a vulnerability

Use [private vulnerability reporting](https://github.com/taha2samy-3/java_buildpack_wolfi/security/advisories/new). Please do not open public issues for security problems.
