The memory helper runs on every start. It reads the limit from `BPL_JVM_TOTAL_MEMORY` or the cgroup (v2 `memory.max`, v1 `memory.limit_in_bytes`). Without a limit it does nothing and the JVM's own ergonomics apply. Flags you set yourself in `JAVA_TOOL_OPTIONS` or `JDK_JAVA_OPTIONS` always win.

## Modes

Choose a mode with `BPL_JVM_MEMORY_MODE`.

### calculated (default)

Every region outside the heap gets a budget first, and the heap gets the rest:

```text
heap = limit
     - headroom          BPL_JVM_HEAD_ROOM % of the limit (default 10)
     - direct memory     10M
     - code cache        240M
     - metaspace         loaded classes x 5800 bytes + 14M
     - thread stacks     BPL_JVM_THREAD_COUNT x 1M (default 250)
```

Loaded classes are estimated as 35% of the classes in the JVM and the application, or set with `BPL_JVM_LOADED_CLASS_COUNT`. If the heap would drop below 32M the container refuses to start and prints the breakdown, rather than being killed later by the kernel.

```text
Memory calculator (container limit 1.0G): heap 360M, metaspace 60M (8436 classes), code cache 240M, direct 10M, stack 1M x 250 threads, headroom 102M
```

### percentage

The original behaviour of this project: `-Xmx` is a fixed share of the limit, 75% by default.

```sh
docker run --memory 2g \
  -e BPL_JVM_MEMORY_MODE=percentage \
  -e BPL_JVM_HEAP_PERCENTAGE=75 \
  my-app
```

### off

Adds no memory flags.

## Pinning the heap

`BPL_JVM_PIN_HEAP=true` adds `-Xms` equal to the calculated `-Xmx`, in either mode. This commits the whole heap at startup, which avoids resize pauses but makes memory use look higher from the first second.

## Tuning tips

- Many threads (reactive servers usually need fewer): lower `BPL_JVM_THREAD_COUNT` to free memory for the heap.
- Native libraries such as Netty's or RocksDB: raise `BPL_JVM_HEAD_ROOM`.
- Small containers (256M to 512M): set `-XX:ReservedCodeCacheSize=64M` in `JAVA_TOOL_OPTIONS`, and the calculator uses your value.
- `MALLOC_ARENA_MAX=2` is set by default to limit glibc arena growth.
